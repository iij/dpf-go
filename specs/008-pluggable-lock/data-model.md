# データモデル: 排他の仕組みを差し替えられるようにする

**機能**: [spec.md](./spec.md) | **計画**: [plan.md](./plan.md) | **日付**: 2026-09-24

本機能は永続データを持たない。排他の状態は実装が持ち、ライブラリは抽象を通して扱うだけで
ある。本ファイルが定めるのは、抽象の形と、ライブラリ側が実行中に持つ状態である。

## 1. 抽象 (`Locker`)

| メソッド | 意味 | 失敗の表し方 |
|---|---|---|
| `Lock(ctx)` | 取得する。待たない | `ErrStillLock`（他者が保持、または自分が保持＝再入） |
| `Renew(ctx)` | **保持を確かめ、必要なら延ばす** | `ErrNotLockHolder`（保持していないと分かった） |
| `Unlock(ctx)` | 解放する。自分が保持者である場合に限る | `ErrNotLockHolder`（保持者でない） |

1 つの値が 1 つのゾーンに対する 1 つの保持者を表す。**対応づけは実装が持つ。**
契約の詳細は [contracts/locker.md](./contracts/locker.md)。

## 2. 任意のインターフェース

| インターフェース | 公開 | 申告する内容 | 申告が無い場合 |
|---|---|---|---|
| `RenewIntervaler` | 公開 | 延長の間隔 | 利用者の指定、それも無ければ既定値 |
| （反映が排他を解くか） | **非公開** | ゾーン反映が排他を解くこと | 解かれないものとして扱う |

公開・非公開の分け方は「誰に関係があるか」で決めている。延長の間隔は外部の実装にこそ
関係があるため公開する。反映が排他を解くのは DPF-API のレコードを使う実装だけの事情で
あるため、`utils` の外からは実装できない形にする（[research.md](./research.md) D4・D5）。

## 3. 実行中の状態

`RunLocked` の実行中にのみ存在する。007 の `hold` を抽象の上へ移したものである。

| 項目 | 内容 |
|---|---|
| 派生 context | 呼び出し側の context から派生し、排他を失った時点で打ち切る |
| 打ち切りの関数 | 派生 context を打ち切る。復帰時にも必ず呼ぶ |
| 延長の停止 | 延長の goroutine を止める合図 |
| 消費の印 | 「この先で排他が解かれる」ことの印。一括置き換えの実装だけが立てる |
| 延長で失われた旨 | 延長が `ErrNotLockHolder` を返したことの記録 |

公開しない。007 の判断（FR-017、一括置き換えの都合を公開 API の形に出さない）をそのまま
引き継ぐ。

## 4. 設定

### 実行の設定（`HoldOption`）

| 項目 | 既定値 | 決まり方 |
|---|---|---|
| 延長の間隔 | 実装の申告 → 利用者の指定 → 既定値 | 利用者の指定があれば申告より優先する |
| 取得の待機 | 待たない | 指定すると、その間隔で取得を繰り返す |

### 一括置き換えの設定（`ApplierOption`）

| 項目 | 既定値 | 備考 |
|---|---|---|
| 排他 | レコードを使う排他 | `WithLocker` で差し替える |
| 既定の排他への設定 | 無し | `WithLockOptions` で渡す。差し替えた場合は意味を持たない |
| 反映のコメント | 空 | 007 の `WithApplyDescription`（`Apply` の引数のまま） |

## 5. 排他の寿命

抽象を挟んでも、007 が定めた寿命の扱いは変わらない。違いは「反映が排他を解くか」の申告に
よって分岐する点だけである。

```text
取得 ──▶ 保持（延長が周期的に走る）──▶ 解放
              │
              ├─ 奪われた ──▶ 派生 context を打ち切る ──▶ 処理の終了を待つ ──▶ 解放を試みる
              │
              └─ 反映が排他を解く実装で、一括置き換えを行う
                        │
                 （延長を止め、消費の印を立てる）
                        ▼
                  残っていた場合に限り解放
```

- 解放は `Unlock` を呼ぶ。保持者でない場合に `ErrNotLockHolder` が返るため、「自分が保持者
  である場合に限り解放する」はこれで満たされる（007 D8 から継承）。
- 消費の印が立っている場合は、`ErrNotLockHolder` を成功として扱う。
- **外部の仕組みを使う排他では、消費の印は立たない。** 一括置き換えの後も通常どおり解放
  される。呼び出し側から見た違いは無い（FR-008）。

## 6. 契約の確認手段

| 項目 | 内容 |
|---|---|
| 入力 | 同じ対象に対する排他を 2 つ作る関数 |
| 確かめること | [contracts/locker.md](./contracts/locker.md) の第 2〜7 節の各項目 |
| 出力 | 満たさない約束があれば、どの約束かを示して失敗させる |

2 つ作るのは、契約の中心が「一方が保持している間はもう一方が取得できない」ことだから
である。1 つでは競合を確かめられない。

参照実装（メモリ内）は、確認の手段が自分自身を確かめる対象であり、利用者が自作するときの
手本でもある。**分散ロックの難しさは再現しない**（[research.md](./research.md) D9）。

## 7. 検証規則の一覧

| 対象 | 規則 | 違反時 | 要件 |
|---|---|---|---|
| `Lock` | 再入を許さない | 確認の手段が検出する | FR-003、契約 第 2 節 |
| `Lock` | 取得できるまで待たない | 同上 | 契約 第 2 節 |
| `Renew` | 保持を失っていると分かる場合は `ErrNotLockHolder` | 同上 | FR-010 |
| `Unlock` | 他者の排他を解放しない | 同上 | 契約 第 4 節 |
| エラー | `errors.Is` で一致する | 同上 | FR-003 |
| 並行呼び出し | 実装が自身で直列化する | 確認の手段が `-race` で検出する | 契約 第 7 節 |
| 差し替え | `Apply` の呼び出し方と結果が変わらない | 単体テスト | FR-008・SC-005 |
| 既定 | 指定しなければレコードを使う排他 | 単体テスト | FR-006 |
