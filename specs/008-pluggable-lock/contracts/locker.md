# 契約: 排他の抽象（実装者向け）

**機能**: [../spec.md](../spec.md) | **計画**: [../plan.md](../plan.md) | **日付**: 2026-09-24

自分で排他の実装を書く人が守るべき約束。**この契約は機械的に確かめられる**
（[../quickstart.md](../quickstart.md) 第 2 節）。

## 1. 必須のメソッド

```go
type Locker interface {
	Lock(ctx context.Context) error
	Renew(ctx context.Context) error
	Unlock(ctx context.Context) error
}
```

1 つの値は 1 つのゾーンに対する 1 つの保持者を表す。**どのゾーンに対応するかを決める責任は
実装にある。** ライブラリは対応づけを知らないため、取り違えても検出できない（FR-015）。

## 2. `Lock` の約束

| 状況 | 返すもの |
|---|---|
| 取得できた | `nil` |
| 他者が保持している | `utils.ErrStillLock` に `errors.Is` で一致するエラー |
| **自分が既に保持している** | 同上。**再入を許してはならない** |
| 打ち切られた | `ctx.Err()` に一致するエラー |
| その他の失敗 | そのエラー（種類を判別できる形のまま） |

- **取得できるまで待ってはならない。** 待つかどうかは呼び出し側が決める。ライブラリは
  取得を繰り返すことで待機を実現する。
- 再入を許さないのは、006 で「自分が保持していれば取得できる」という判定が同一ユーザ間の
  排他を完全に無効にしたためである。保持期間を延ばしたい場合は `Renew` を使う。

## 3. `Renew` の約束

**「保持を確かめ、必要なら延ばす」操作である。** 延ばすことだけが目的ではない。

| 状況 | 返すもの |
|---|---|
| まだ保持しており、延長も成功した（または延長が不要） | `nil` |
| **保持していないと分かった** | `utils.ErrNotLockHolder` に `errors.Is` で一致するエラー |
| 一時的に確かめられなかった（通信の失敗など） | そのエラー。ライブラリは次の周期で再試行する |

- 保持を確かめる手段を持たない実装は、常に `nil` を返してよい。ただしその場合、処理の
  途中で排他を失っても検知できない。この限界を実装の文書に明記すること（FR-010b）。
- 保持の維持を背景で行う仕組み（リースの自動更新など）では、**延ばす処理は不要でも
  確かめる処理は必要である。** 何もせず `nil` を返すと、失った状態のまま処理が走り続ける。

## 4. `Unlock` の約束

| 状況 | 返すもの |
|---|---|
| 解放できた | `nil` |
| 自分が保持者でない（既に失っている） | `utils.ErrNotLockHolder` に一致するエラー |
| 排他がそもそも存在しない | `nil`（何もせず成功） |
| その他の失敗 | そのエラー |

- **他者が保持している排他を解放してはならない。**

## 5. 任意のインターフェース

実装しなくてもよい。実装すると、ライブラリの振る舞いが変わる。

```go
type RenewIntervaler interface {
	RenewInterval() time.Duration
}
```

延長の間隔を申告する。申告が無い場合、ライブラリは利用者の指定を使い、それも無ければ
既定値を使う。保持期間から導ける実装は申告すること（利用者が保持期間を変えるたびに間隔を
指定し直さずに済む）。

**「ゾーン反映が排他を解くか」を申告する任意のインターフェースもあるが、非公開である。**
`utils` の外からは実装できない。これが必要なのは DPF-API のレコードを使う実装だけであり、
外部のミドルウェアを使う排他で反映が排他を解くことはないためである
（[../research.md](../research.md) D4）。

## 6. エラーの約束

- `utils.ErrStillLock` と `utils.ErrNotLockHolder` は `errors.Is` で一致すること。ラップは
  してよい（`fmt.Errorf("...: %w", utils.ErrStillLock)` など）。
- この 2 つを取り違えてはならない。**「取得できなかった」は待てば取れるかもしれない状態、
  「保持者でない」は既に失った状態である。** ライブラリは前者を再試行の対象とし、後者を
  処理の打ち切りの合図として扱う。

## 7. 並行性の約束

- 1 つの値に対する `Lock` / `Renew` / `Unlock` は、複数の goroutine から同時に呼ばれうる。
  ライブラリは延長を別の goroutine で行うためである。**実装は自身で直列化すること。**

## 8. 実装できているかの確認

```go
import "github.com/iij/dpf-go/utils/lockertest"

func TestMyLocker(t *testing.T) {
	lockertest.Run(t, func(t *testing.T) (utils.Locker, utils.Locker) {
		// 同じ対象に対する排他を 2 つ返す
		return newMyLocker("zone-1"), newMyLocker("zone-1")
	})
}
```

2 つ返すのは、契約の中心が「一方が保持している間はもう一方が取得できない」ことだから
である。確認の手段は、契約のどの約束に反しているかを示す（FR-012）。
