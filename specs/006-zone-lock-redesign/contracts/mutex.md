# 契約: 公開 API (`utils.Mutex`)

**機能**: [../spec.md](../spec.md) | **計画**: [../plan.md](../plan.md) | **日付**: 2026-09-18

`utils` パッケージが公開する排他の契約。署名は実装時に確定するが、**外から見える約束**は
本ファイルを正とする。

## 1. 生成

```go
func NewMutex(cr dpf.RecordsApi, zoneID string, opts ...Option) *Mutex
```

- **シグネチャは変更しない。** 追加の API クライアントも引数も取らない
  （[../research.md](../research.md) D4・D5・D6）。
- `cr` には `client.RecordsAPI` をそのまま渡せる。
- 返された `*Mutex` は 1 つの保持者を表す。**インスタンスを共有して複数の処理から同時に
  取得することはできない**（2 つ目は `ErrStillLock` になる）。並行して別々に排他を取る場合は
  インスタンスを分ける。
- ネットワークへ出ない。生成時に検証するのは Option の値のみ。

### `dpf.RecordsApi` の拡張（破壊的変更）

| メソッド | 状態 | 用途 |
|---|---|---|
| `GetRecordList` | 既存 | SOA と専用レコードの取得、反映の確認 |
| `PatchRecord` | 既存 | SOA のラベルの書き込み |
| `PostRecord` | **追加** | 専用レコードの追加（一時ロックの取得） |
| `DeleteRecordChanges` | **追加** | 追加予定の取り消し（一時ロックの解放） |
| `DeleteRecord` | **追加** | 反映済みの専用レコードの削除（FR-008 の回復） |

`*dpf.RecordsAPIService` は追加後も満たす。影響を受けるのは自分で実装している利用者のみ。

## 2. 操作

| メソッド | 事前条件 | 事後条件（成功時） | 主なエラー |
|---|---|---|---|
| `Lock(ctx)` | 排他を保持していない | SOA に owner と奪ってよい時刻が書かれ、読み出せることを確認済み。専用レコードは残っていない | `ErrStillLock` / `ErrLabelLimit` |
| `LockWait(ctx, interval)` | 同上 | 同上 | `ErrStillLock` 以外のエラー、`ctx.Err()` |
| `Renew(ctx)` | 自分が保持者である | 奪ってよい時刻が現在時刻 + TTL へ進む | `ErrNotLockHolder` |
| `Unlock(ctx)` | 自分が保持者である、または排他が存在しない | 奪ってよい時刻が現在時刻になり、他者が取得できる | `ErrNotLockHolder` |

共通の約束:

- **いずれもゾーンへの反映を行わない**（FR-024）。
- `ctx` の打ち切りに従う。打ち切られた場合は `ctx.Err()` を返す。
- 失敗した場合、一時レコード追加ロックを保持したままにしない（FR-009）。
- 実際の API 呼び出しの順序は [lock-record.md](./lock-record.md) 第 2 節を正とする。

### `Lock` の約束

0. **取得できないと分かっている場合は、専用レコードを作らずに終える。** 一時レコード追加
   ロックを取得する前に SOA のラベルを読み、取得できない場合はその時点で `ErrStillLock` を
   返す（FR-002）。この事前判定は早く諦めるためだけに用い、書き込みの根拠にはしない
   （FR-003）。取得できる場合の呼び出しは 8 回、この経路で終える場合は 1 回である
   （[lock-record.md](./lock-record.md) 第 2 節）。
1. **再入できない。** 自分自身が保持している場合も `ErrStillLock` を返す（FR-017）。
   保持期間を延ばす場合は `Renew` を使う。
2. 取得できるのは「奪ってよい時刻を過ぎている」「ラベルが無い」「値が解釈できない」場合
   のみ（FR-018・FR-019）。owner は判定に用いない。
3. 復帰した時点で、書き込んだ内容が**読み出せることを確認済み**である（FR-020）。
   確認できない場合は取得に失敗したものとして扱い、`ErrStillLock` を返す。
4. SOA のラベル数が上限を超える場合は、書き込みを試みずに `ErrLabelLimit` を返す（FR-014）。
5. SOA に既に付いている他のラベルを変更・削除しない（FR-013）。

### `Renew` の約束

- 保持者の確認は SOA の `owner` ラベルが自分の owner と一致することで行う。
- 延長の書き込みも `Lock` と同じ確認を行う。確認できない場合（延長の最中に奪われた場合を
  含む）は `ErrNotLockHolder` を返す。
- 一時レコード追加ロックは取得しない（[../research.md](../research.md) D11）。

### `Unlock` の約束

- 排他（`deadline` ラベル）が存在しない場合は、何もせずに成功を返す（FR-025）。
- `owner` が自分でない場合は、**他者の排他を変更せず** `ErrNotLockHolder` を返す（FR-024）。
  `defer` で呼ぶ利用者が、奪われていた事実を検知できるようにするためである。

## 3. Option

| Option | 対象 | 既定値 | 0 値・空値の扱い |
|---|---|---|---|
| `WithOwner(string)` | 保持者 | [../data-model.md](../data-model.md) 第 3 節 | 空文字は無視（既定のまま） |
| `WithTTL(time.Duration)` | 保持期間 | 15 分 | 0 以下は無視 |
| `WithLockRecordTTL(time.Duration)` | 一時ロックの失効まで | 1 分 | 0 以下は無視 |
| `WithVerifyTimeout(time.Duration)` | 反映確認の上限 | 10 秒 | 0 以下は無視 |
| `WithLockRecordLabel(string)` | 専用レコードの最左ラベル | `_dpf-go-lock` | 空文字は無視 |
| `WithLockRecordContent(rrtype, rdata)` | 専用レコードの RRTYPE と rdata | `TXT` / `"dpf-go lock"` | 空の rdata は無視 |

「0 以下・空文字は無視して既定のまま」は既存の `WithOwner` / `WithTTL` の作法に合わせる
（憲章 原則 V の「既定値は保守的に」）。

## 4. 番兵エラー

| エラー値 | 意味 | 返る場面 |
|---|---|---|
| `ErrStillLock`（既存） | まだ奪えない排他に対して取得を試みた | 他者が保持中、自分が保持中（再入）、一時ロックが保持中、反映の確認に失敗 |
| `ErrNotLockHolder`（新規） | 自分が保持者でない | `Renew` / `Unlock` |
| `ErrLabelLimit`（新規） | SOA のラベル数が上限に達している | `Lock` |
| `ErrRecordNotFound`（既存） | SOA レコードが見つからない | すべての操作 |

- いずれも `errors.Is` で判別できる。
- API 由来のエラーはラップせずそのまま返す。`*dpf.GenericOpenAPIError` として
  `errors.As` で取り出し、`error_details` を参照できる状態を保つ。
- **`ErrStillLock` は「取得できなかった」という 1 つの意味に統一する。** 原因（他者が保持
  中か、一時ロックが取れなかったか、確認に失敗したか）でエラーを分けない。呼び出し側の
  対処が「待って再試行する」の一択であり、分けても使い道が無いためである。
- 上記に当てはまらない想定外の状態は、番兵を設けずにその場で組み立てたエラーとして返す。
  該当するのは次の 2 つで、いずれも呼び出し側が場合分けして対処できるものではない。
  SOA の行が一意に決まらない場合（[../research.md](../research.md) D10）と、一時レコード
  追加ロックの解放を確認できない場合（[lock-record.md](./lock-record.md) 第 4 節）。

## 5. godoc に明記すること (FR-029)

1. **排他の強さが競合相手によって異なること。**
   - 別ユーザとの間: DPF-API が編集中のレコードへの他ユーザの編集を拒否するため、
     サーバ側で保証される。
   - 同一ユーザとの間: 一時レコード追加ロックの取得と解放によって成立する。
   - 同一プロセス内の別インスタンス: 同一ユーザと同じ仕組みで排他される。
2. **取得が再入できないこと**と、延長は `Renew` であること。
3. **`WithOwner` に一意でない値を渡した場合に何が壊れるか**（排他は壊れない。延長・解放の
   宛先の判別が壊れる）。
4. **取得・延長・解放がゾーン反映を行わないこと**、および Lock 後にレコードを編集して
   SOA ごと反映する使い方を想定していること（003 から継承）。
5. **専用レコードが権威サーバへ公開される可能性**（保持中に他者がゾーン反映した場合）と、
   その場合に自力で回復すること、回復の結果として利用者の編集差分に削除予定が 1 件加わる
   こと（FR-008）。
6. SOA のラベルを 2 つ使うため、利用者が自由に使えるのは 8 個までであること（FR-014）。
