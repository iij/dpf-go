# 機能仕様: 一括置き換えが排他を解くことの申告の仕組みを取り除く

**機能ブランチ**: `010-remove-apply-consume`

**作成日**: 2026-09-29

**状態**: ドラフト

**憲章**: v2.0.1 の原則 II (テストを伴う実装)、原則 III (godoc と文書の同時更新)、原則 V (ライブラリとしての規律) に整合

**入力**: 利用者による記述: "010として、consumedByZoneApply / consumesLockOnZoneApply / hold.consumeを削除します"

**関連**: 007-zone-atomic-apply（FR-017 でこの扱いを定めた）、008-pluggable-lock（申告を非公開インターフェースで行うと決めた）、009-zone-label-lock（排他の置き場を移した結果、申告する実装が無くなった）

## 利用シナリオと検証 *(必須)*

### 利用シナリオ 1 - 到達しないコードが残らない (優先度: P1)

009 で排他の状態がゾーンのラベルへ移り、**「一括置き換えがこの排他を解く」と申告する実装が
1 つも無くなった。** 申告は本パッケージの外からは行えない形になっているため、**将来も現れ
ない**（本パッケージの中に新しい実装を足す場合を除く）。

その結果、次の一式が到達しないまま残っている。申告の宣言、申告を問い合わせる判定、判定に
従って立てる印、そして印に依存する解放時の分岐である。本機能はこれを取り除く。

読み手にとっての害は 2 つある。**動かない分岐を「動くもの」として読んでしまう**こと、および
**その分岐を説明する長いコメント（なぜ印を立てるのか、どの位置で立てるのか）が、現在は
起こらない状況の説明に紙面を使っている**ことである。

**この優先度の理由**: 本機能の目的そのものである。単独で価値があり、これだけで完結する。

**独立した検証**: 取り除いた後に、排他の取得・延長・解放と、ゾーン全体の一括置き換えが
従来どおり動くことで検証できる。公開 API に変化が無いことも確かめる。

**受け入れシナリオ**:

1. **前提** 排他を保持している、**操作** 取得・延長・解放を行う、**結果** 従来と同じ結果になる
2. **前提** 排他を保持している、**操作** ゾーン全体の一括置き換えと反映を行う、**結果** 反映の後も排他は保持され、終了時に通常どおり解放される（009 と同じ）
3. **前提** 排他の仕組みを差し替えている、**操作** ゾーン全体の一括置き換えを行う、**結果** 既定の排他と同じ結果になる
4. **前提** 本機能の変更を適用した、**操作** 公開されている要素の一覧を確認する、**結果** 取り除かれた要素も追加された要素も無い
5. **前提** 解放が「保持者でない」で失敗した、**操作** 戻り値を確認する、**結果** そのエラーがそのまま返る（成功として扱われる経路が無い）

---

### 利用シナリオ 2 - 仕様の記述が実態と一致する (優先度: P2)

007 は「一括置き換えは排他を解くため、その実行前に自動延長を止め、終了時の解放も行わない
ようにしなければならない」と定めている（FR-017）。008 はその申告を非公開の形で行うと定めて
いる。**どちらも現在は成立しない。**

009 で 007 の仕様には注記を入れたが、**仕組みそのものが無くなることは書かれていない。**
008 の仕様には注記も無い。仕様を読んだ人が、存在しない仕組みを探すことになる。

**この優先度の理由**: 利用シナリオ 1 の結果として必要になる追随であり、単独で開発するもの
ではない。ただし読み手にとっての価値は独立している。

**独立した検証**: 007 と 008 の仕様を読み、現在の実装に無い仕組みを探すことにならないかで
検証できる。

**受け入れシナリオ**:

1. **前提** 007 の仕様を読む、**操作** FR-017 が求める扱いを実装に探す、**結果** その扱いが不要になった経緯と、仕組みが取り除かれたことが仕様から辿れる
2. **前提** 008 の仕様を読む、**操作** 申告の仕組みを実装に探す、**結果** 取り除かれたことと、その理由が仕様から辿れる

---

### 境界的な状況

- 将来ふたたび「反映が排他を解く」実装を足したくなった場合はどうするか。申告の仕組みを
  復活させる必要がある。設計の経緯は 007・008 の仕様と本機能の記録に残り、コードは版管理の
  履歴から辿れる。**先回りして残しておくことはしない**
- 本パッケージの外で排他を実装している利用者への影響はあるか。**無い。** 申告は本パッケージの
  外からは行えない形であり、外部の実装は最初から申告していない
- 印に依存する解放時の分岐（印が立っている場合に「保持者でない」を成功として扱う）を取り除く
  と、解放の失敗はすべてそのまま返るようになる。**印が立つ経路が無いため、実際の挙動は
  変わらない**

## 要件 *(必須)*

### 機能要件

**取り除く**

- **FR-001**: 「一括置き換えがこの排他を解く」ことの申告の仕組みを、すべて取り除かなければならない。対象は、申告の宣言、申告を問い合わせる判定、判定に従って立てる印、印を読み出す手段、および印に依存する解放時の分岐である
- **FR-002**: 取り除いた後に、到達しないコードを残してはならない

**変えない**

- **FR-003**: 公開されている要素を変えてはならない。取り除くのも追加するのもいけない
- **FR-004**: 排他の取得・延長・解放の結果を変えてはならない
- **FR-005**: ゾーン全体の一括置き換えの呼び出し方と結果を変えてはならない。反映の後も排他が保持され、終了時に通常どおり解放されること（009 で定めた挙動）を保たなければならない
- **FR-006**: 排他の仕組みを差し替えた場合と既定の場合で、結果が変わってはならない（008 で定めた性質）

**文書**

- **FR-007**: 007 の仕様へ、FR-017 が求めた扱いが不要になったことに加え、**仕組みそのものを取り除いたこと**を追記しなければならない
- **FR-008**: 008 の仕様へ、申告の仕組みを取り除いたことと、その理由を追記しなければならない
- **FR-009**: 実装に残るコメントのうち、申告の仕組みを前提とした記述を取り除かなければならない

**検証**

- **FR-010**: 申告と印に関する単体テストを取り除かなければならない。取り除いたことで壊れないことは、排他の取得・延長・解放と一括置き換えの既存のテストで担保する
- **FR-011**: 実 API での確認を `integration` の区分で行わなければならない。挙動を変えないため、既存の統合テストが通ることをもって確認とする

### 主要な実体

- **申告の宣言**: 排他の実装が「一括置き換えによって自分が解かれる」ことを表明する手段。本パッケージの外からは行えない形になっている（`consumedByZoneApply`）
- **申告の判定**: 排他が申告しているかを問い合わせる手段（`consumesLockOnZoneApply`）
- **印**: 判定の結果に従って立てる、「この先で排他が解かれる」ことを表す状態。自動延長を止め、解放の扱いを変える（`hold.consume` とその状態・読み出し）

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: 申告の仕組みに属する到達しないコードが 0 件である
- **SC-002**: 公開されている要素の差分が 0 件である
- **SC-003**: 排他の取得・延長・解放の結果が変わる事象が 0 件である
- **SC-004**: ゾーン全体の一括置き換えの結果が変わる事象が 0 件である。反映の後も排他が保持され、解放が成功する
- **SC-005**: 排他を差し替えた場合と既定の場合で結果が変わる事象が 0 件である
- **SC-006**: 007 と 008 の仕様を読んだ人が、実装に存在しない仕組みを探す事象が 0 件である（取り除いたことが仕様から辿れる）

## 前提

- 009-zone-label-lock によって、既定の排他は「一括置き換えが排他を解く」と申告しなくなった。**申告する実装は 1 つも無い**
- 申告は本パッケージの外からは行えない形である（008 の決定）。したがって利用者が申告する実装を書くことはできず、**本機能の後も現れない**
- **公開されている要素は変わらないため、破壊的変更ではない。** 利用者に見える挙動も変わらないため、`CHANGELOG.md` への記載は憲章 原則 III が求める条件（利用者に見える挙動の変更）に該当しない。内部の整理として記載することは妨げない
- 印に依存する解放時の分岐を取り除くと、解放の失敗はすべてそのまま返るようになる。印が立つ経路が無いため実際の挙動は変わらない
- 将来ふたたび必要になった場合は、版管理の履歴と 007・008 の仕様から復元できる。先回りして残さない

**範囲の境界**

- 008 で定めた排他の抽象そのもの（取得・延長・解放の 3 つ）は変更しない
- 延長の間隔の申告（実装が任意で行うもの）は変更しない。これは現役の仕組みである
- 契約の確認手段（`utils/lockertest`）は変更しない
- 排他の状態の置き場、保持期間、延長の間隔、取得を待つかどうかといった挙動は変更しない
