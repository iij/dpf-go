# 実装計画: 一括置き換えが排他を解くことの申告の仕組みを取り除く

**ブランチ**: `010-remove-apply-consume` | **日付**: 2026-09-29 | **仕様**: [spec.md](./spec.md)

**入力**: 次の機能仕様 `/specs/010-remove-apply-consume/spec.md`

**注記**: 上の「ブランチ」は `.specify/feature.json` が示す機能ディレクトリ名である。実際の
git ブランチは `009-zone-label-lock`（009 のコミットが載っている）。実装に入る前に切る。

## 概要

007 は「一括置き換えは排他を解く」ことを前提に、反映の前に自動延長を止め、終了時の無条件の
解放を避ける扱いを入れた。008 はその申告を**本パッケージの外からは実装できない非公開の形**で
行うと決めた。009 で排他の状態がゾーンのラベルへ移り、**申告する実装が 1 つも無くなった。**

外からは実装できない以上、申告する型は将来も現れない。残っているのは到達しないコードである。
本機能はこれを取り除く。

方針は 3 つある。

1. **丸ごと取り除く。** 宣言・判定・印・印に依存する解放の分岐のすべてである。判定だけ残して
   `false` を返す形にはしない（同じ問題が残り、説明だけが増える）。復活が必要になった場合は
   版管理の履歴と 007・008 の記録から復元する（[research.md](./research.md) D1）。
2. **挙動を変えない。** 公開されている要素も、排他の結果も、一括置き換えの結果も変えない。
   取り除く分岐は**現在も通らない**ため、実際に通る経路は 1 つも変わらない（同 D3）。
3. **既存のテストを 1 行も変えずに通す。** 落とすのは、取り除いた要素を直接検証していた
   テストだけである。**落とすテストが増えるなら、取り除く範囲が広すぎる**（同 D5）。

利用者に見える変化は無い。ここでいう価値の受け手は**本リポジトリを保守する人**である
（仕様 利用シナリオ 1）。

## 技術的な前提

**言語 / バージョン**: Go 1.27（`go.mod` の指定に従う）

**主要な依存**: 変更しない。**新しい依存は追加しない**

**保存先**: 該当なし（コードの削除のみ）

**テスト**: `go test`。**既存のテストが検証の中心**である。単体テストはネットワーク不要、実 API
に触れる確認は `integration` ビルドタグで隔離

**対象環境**: ライブラリ。利用者のプロセスで動く

**プロジェクト種別**: library（`github.com/iij/dpf-go` の `utils` パッケージ）

**性能目標**: 変わらない（API の呼び出し回数も分岐の数も実質的に変わらない）

**制約**: 公開されている要素を変えないこと。挙動を変えないこと

**規模 / 範囲**: 手を入れるのは `utils/locker.go` と `utils/apply.go` の 2 ファイル、テスト 2
ファイル、仕様 3 ファイル。**正味は削除である**
