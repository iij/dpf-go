# 契約: 公開 API は変わらない

**機能**: [spec.md](../spec.md) | **計画**: [plan.md](../plan.md) | **日付**: 2026-09-29

本機能の契約は「**何も変わらないこと**」である。取り除く対象がすべて非公開であるため、
利用者から見える形は変化しない。これを明示的な受け入れ条件として置く。

## 1. 変わらないもの

| 対象 | 約束 |
|---|---|
| 公開されている型・関数・メソッド・定数・エラー値 | **追加も削除も変更もしない** |
| `Locker` の契約（取得・延長・解放） | 変えない |
| `RunLocked` / `Mutex.Do` の挙動 | 変えない |
| `ZoneApplier.Apply` の呼び出し方と結果 | 変えない。反映の後も排他は保持され、終了時に通常どおり解放される |
| 排他を差し替えた場合と既定の場合の同一性 | 変えない |
| 延長の間隔の申告（`RenewIntervaler`） | 変えない。**これは現役の仕組みである** |

## 2. 取り除くもの（すべて非公開）

| 要素 | 公開/非公開 | 外部への影響 |
|---|---|---|
| 一括置き換えが排他を解くことを申告するインターフェース | **非公開** | 無し。外からは実装できない |
| 同じ申告を問い合わせる判定 | **非公開** | 無し |
| 「この先で排他が解かれる」ことの印と、その操作 | **非公開** | 無し |
| 印に依存する解放時の分岐 | **非公開** | 無し。印が立つ経路が無いため現在も通らない |

## 3. 確認の方法

公開されている要素に差分が無いことは、機械的に確かめられる。

```bash
go doc -all ./utils > /tmp/after.txt   # 変更の前後で取得して比較する
```

差分が出た場合は、取り除く対象を誤っている。

## 4. 検証の考え方

**挙動を変えない変更であるため、既存のテストが無変更で通ることが最大の検証である。**
取り除いた要素を直接検証していたテストだけを落とし、それ以外は 1 行も変えない。落とす必要が
あるテストが増えるなら、取り除く範囲が広すぎる。
