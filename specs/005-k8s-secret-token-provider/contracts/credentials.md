# 契約: 接続情報の選択と名前空間の決定

**機能**: Kubernetes Secret からのトークン取得 | **日付**: 2026-09-18

**関連**: [spec.md](../spec.md) | [research.md](../research.md) D3・D4・D5・D6 | [api.md](./api.md)

`NewTokenProviderFromEnvironment` が実行環境を読む部分の契約である。本機能でもっとも
挙動が環境に依存する箇所であり、決定表として固定する。

**前提**: 候補の選択と接続設定の組み立ては `k8s.io/client-go` に委ねる
（[research.md](../research.md) D3）。本契約は、委ねた結果として成り立つ挙動と、
本パッケージが自前で担う名前空間の決定を定める。

---

## 1. 候補の選択 (FR-020)

Kubernetes の標準的なクライアントと同じ順序である。独自の順序は持たない。

| 順 | 候補 | 選ばれる条件 |
|---|---|---|
| 1 | 設定ファイル（`KUBECONFIG` が設定されていればそれが指すもの、設定されていなければ `~/.kube/config`） | そこから接続情報が得られる |
| 2 | クラスタ内で割り当てられた資格情報 | 候補 1 から接続情報が得られず、かつトークンファイルが存在し `KUBERNETES_SERVICE_HOST` と `KUBERNETES_SERVICE_PORT` がいずれも空でない |

どちらも成り立たなければ、生成時に `ErrNoCredentials` を返す (FR-021)。

### 約束

- **`KUBECONFIG` と `~/.kube/config` は 1 つの候補である。** `KUBECONFIG` が設定されて
  いれば `~/.kube/config` は読まれない。両者の間にクラスタ内の資格情報は入らない
- `KUBECONFIG` が複数のパスを含む場合 (`:` 区切り) は、`clientcmd` の merge 規則に
  委ねる。本パッケージは分割も優先順位づけも行わない
- 候補 2 の判定条件は client-go の `Possible()` と同一である
  （[research.md](../research.md) D5）。独自の条件を持たない
- 候補の判定は接続を伴わない。API サーバへの到達性は確認しない。生成時に
  ネットワークへ出ないため、単体テストが接続を必要としない (SC-012)
- **設定ファイルがすべて欠けている場合に警告を出さない。** `ClientConfigLoadingRules`
  の `Warner` に何もしない関数を設定する。未設定のままだと client-go が `klog` へ
  書くが、FR-023 により「設定ファイルが無い」は正常な経路であり、警告は不適切である。
  大域の `klog` 設定には触れない (FR-035、憲章 原則 V)

### 設定ファイルの状態ごとの扱い (FR-022・FR-023)

| 状態 | 扱い | 要件 |
|---|---|---|
| 存在しない | その候補は無いものとして候補 2 へ進む。**失敗として扱わない** | FR-023 |
| 存在するが解釈できない（YAML が壊れている等） | エラー。**候補 2 へ移らない** | FR-022 |
| 存在し解釈できるが、接続情報として空 | 候補 2 へ進む | FR-023 |
| 存在し、接続先の指定に誤りがある（参照先の cluster が無い等） | エラー。候補 2 へ移らない | FR-022 |
| 存在し、`current-context` が解決できない名前を指す | エラー。候補 2 へ移らない | FR-022 |
| 存在し、`current-context` が書かれていない | 接続情報が空であるため候補 2 へ進む | FR-023 |

**下 2 行は実装時に client-go の挙動として確認した** (2026-09-18)。当初は名前空間の
決定の段で `ErrNamespaceUnknown` になると書いていたが、いずれも**その手前**で
判定される。`current-context` が解決できない設定は接続情報として使えないため
FR-022 のエラーになり、`current-context` が無い設定は接続情報が空であるため
FR-023 により次の候補へ進む。名前空間の決定に到達するのは、選択中の接続先が
解決できたうえで `namespace` だけが書かれていない場合である。

「存在しない」を失敗としないのは、存在しないファイルを指す環境変数で全体が止まるより、
設定を持たない環境として扱う方が実務に合うためである。標準的なクライアントも同じ扱いを
する（[research.md](../research.md) D3 の実測表）。

### 8 通りの組み合わせ (SC-007・SC-008)

`K` = `KUBECONFIG` が設定され、そこから接続情報が得られる。
`H` = `~/.kube/config` が存在し、そこから接続情報が得られる。
`I` = クラスタ内の資格情報が利用可能（`Possible()` が真）。

| # | K | H | I | 選ばれる候補 |
|---|---|---|---|---|
| 1 | × | × | × | なし → `ErrNoCredentials` |
| 2 | × | × | ○ | 2: クラスタ内 |
| 3 | × | ○ | × | 1: `~/.kube/config` |
| 4 | × | ○ | ○ | 1: `~/.kube/config` |
| 5 | ○ | × | × | 1: `KUBECONFIG` |
| 6 | ○ | × | ○ | 1: `KUBECONFIG` |
| 7 | ○ | ○ | × | 1: `KUBECONFIG` |
| 8 | ○ | ○ | ○ | 1: `KUBECONFIG` |

`K` が真のとき `~/.kube/config` は読まれない（#7・#8）。設定ファイルが使えるとき
クラスタ内の資格情報は使われない（#4・#6・#8）。**8 通りすべてで、標準的な
クライアントの選択と一致する** (SC-008)。

## 2. 名前空間の決定 (FR-013・FR-014)

`WithNamespace` が空でない値で指定されていれば、常にそれを使う。指定が無い場合は
**選ばれた候補に紐づく値だけ**を読む。

| 選ばれた候補 | 導出元 | 空・読めない場合 |
|---|---|---|
| 1（設定ファイル） | 解釈前の設定 (`RawConfig()`) の `Contexts[CurrentContext].Namespace` | `ErrNamespaceUnknown` |
| 2（クラスタ内） | `/var/run/secrets/kubernetes.io/serviceaccount/namespace`（前後の空白を除去） | `ErrNamespaceUnknown` |
| — （`NewTokenProvider` でクライアントを注入） | なし | `ErrNamespaceUnknown` |

### 約束

- **`"default"` を補わない** (FR-014)。client-go の `Namespace()` は決まらないときに
  `"default"` を返すため、これを使わず `RawConfig()` から直接読む
  （[research.md](../research.md) D4）
- **候補をまたいで回り込まない。** 候補 1 が選ばれ、その context に名前空間が
  書かれていない場合、クラスタ内の名前空間の値が読める状態にあってもそれを使わない。
  `ErrNamespaceUnknown` とする（受け入れシナリオ 2-12）。**ここが client-go の
  `Namespace()` との違いである**。client-go は回り込み、最後に `"default"` を補う
- **`POD_NAMESPACE` を参照しない**（同 D6）。資格情報が持つ値ではないため
- 名前空間の決定は生成時に行う。評価時に持ち越さない (SC-006)

### 接続先の選択は標準に合わせ、名前空間は合わせない理由

接続先を取り違えた場合は認証が失敗し、利用者が気づける。名前空間を取り違えた場合は
**別の Secret を読んで成功しうる**。誤りの重さが違うため、扱いを分ける。

### 決定の順序（生成時）

```text
1. client-go に接続設定を組み立てさせる  → ErrEmptyConfig なら ErrNoCredentials
                                            それ以外のエラーは包んで返す
2. どの候補が選ばれたかを判定する        → 名前空間の導出元を決めるため
3. 名前空間を決める                      → WithNamespace 優先、無ければ導出、
                                            導けなければ ErrNamespaceUnknown
4. 取得処理を返す
```

1〜3 のいずれで失敗しても、取得処理は返らない。**評価しなければ分からないエラーは
Secret の内容と権限だけである**（[data-model.md](../data-model.md) 第 5 節）。

## 3. 検証の観点

単体テストで固定すべき点。いずれもネットワークと動作中のクラスタを必要としない。

| 観点 | 方法 |
|---|---|
| 8 通りの選択 (SC-007) | 環境変数と、一時ディレクトリに置いたファイルの有無・内容を組み合わせる。パスは注入可能にする |
| client-go の選択との一致 (SC-008) | 同じ探索規則を渡した `clientcmd.NewNonInteractiveDeferredLoadingClientConfig` の結果と接続先を比較する。**クラスタ内を模擬した組み合わせは比較できない**（client-go の `Possible()` は固定パスを読み、テストが用意した資格情報を見られない）。その 4 通りは選択の表による検証が受け持つ |
| `KUBECONFIG` が設定ファイルより優先される | 双方を用意し、`KUBECONFIG` 側の接続先が使われることを確認する |
| 設定ファイルがクラスタ内の資格情報より優先される | 双方を利用可能にし、設定ファイルが使われることを確認する |
| `KUBECONFIG` が存在しないファイルを指す | エラーにならず、候補 2 へ進むことを確認する (FR-023) |
| 設定ファイルが壊れている | エラーになり、候補 2 へ移らないことを確認する (FR-022) |
| 候補が無い | `ErrNoCredentials` になることを確認する。`clientcmd.IsEmptyConfig` の判別に依存する箇所である |
| 名前空間の導出（2 経路） | context に `namespace` を書いた設定、書かない設定、namespace ファイルの有無で確認する |
| `current-context` の問題が名前空間の手前で判定される | 解決できない名前を指す設定はエラー、書かれていない設定は次の候補へ進むことを確認する |
| `"default"` を補わない | context に `namespace` が無い設定で `ErrNamespaceUnknown` になることを確認する |
| 候補をまたいで回り込まない | 設定ファイルを選ばせ、その context に `namespace` を書かず、namespace ファイルは読める状態にして `ErrNamespaceUnknown` になることを確認する |
| `POD_NAMESPACE` を無視する | 当該環境変数を設定し、namespace ファイルが無い状態で `ErrNamespaceUnknown` になることを確認する |
| 生成時にネットワークへ出ない | 到達しない接続先を指す設定で、生成が成功することを確認する |

**テスト容易性のための要求**: クラスタ内の資格情報の 2 つのファイルパス、および
設定ファイルの探索規則（`ClientConfigLoadingRules`）は、パッケージ内部で差し替え
可能にする（非公開の変数、または内部の構造体のフィールド）。公開 API には出さない。
実ファイルシステムの固定パスと実際の `$HOME` に依存すると、上記の観点を単体テストで
固定できない。
