# データモデル: 排他を保持したままの実行と、ゾーン全体の一括置き換え

**機能**: [spec.md](./spec.md) | **計画**: [plan.md](./plan.md) | **日付**: 2026-09-18

本機能は永続データを持たない。排他の状態は 006 のとおり DPF-API 上のレコードとラベルとして
保持する。本ファイルが定めるのは、実行中にプロセス内に存在する状態と、その遷移である。

## 1. 実行中の状態 (`hold`、非公開)

`Do` の実行中にのみ存在する。`Do` が復帰した時点で破棄される。

| 項目 | 内容 |
|---|---|
| 派生 context | 呼び出し側の context から派生し、排他を失った時点で打ち切る |
| 打ち切りの関数 | 派生 context を打ち切る。`Do` の復帰時にも必ず呼ぶ |
| 延長の停止 | 延長の goroutine を止める合図 |
| 消費の印 | 「この先で排他が解かれる」ことの印。一括置き換えの実装だけが立てる |
| 延長で失われた旨 | 延長が「保持者でない」を返したことの記録 |

**公開しない。** 一括置き換えが排他を解くという事情を公開 API の形に出さないため
（FR-017、[research.md](./research.md) D7）。

## 2. 設定

### 排他の設定（006 から継承）

| 項目 | 既定値 | 変更手段 |
|---|---|---|
| 保持者 | インスタンスごとに一意な値 | `WithOwner` |
| 保持期間 | 15 分 | `WithTTL` |
| 一時レコード追加ロックの失効 | 1 分 | `WithLockRecordTTL` |
| 反映確認の上限 | 10 秒 | `WithVerifyTimeout` |
| 専用レコードの最左ラベル / 内容 | `_dpf-go-lock` / TXT | `WithLockRecordLabel` / `WithLockRecordContent` |

### 本機能で追加する設定

| 項目 | 既定値 | 変更手段 | 根拠 |
|---|---|---|---|
| 延長の間隔 | 保持期間の 1/3（既定では 5 分） | `WithRenewInterval` | FR-003、[research.md](./research.md) D6 |
| 取得の待機 | 待たない | `WithLockWait`（間隔を指定すると待つ） | FR-011 |
| 反映のコメント | 空 | `WithApplyDescription` | FR-020 |

### 固定する値（変更手段を設けない）

| 項目 | 値 | 根拠 |
|---|---|---|
| SOA レコードを取り込むか | 取り込まない | FR-015 |
| Zone Apex の NS レコードを取り込むか | 取り込まない | FR-016 |

これらは既定値ではなく、本機能が成立するための前提である。変更を許せば排他が壊れる
（[plan.md](./plan.md)「2 つのフラグを Option にしないことについて」）。

## 3. 編集の内容を表す関数

```text
(打ち切りを伝えられる引数, 反映したいレコードの一覧) → (反映したいレコードの一覧, エラー)
```

- **入力と出力は同じ型である**（[research.md](./research.md) D9b）。公開されているレコード
  からこの型への変換は本操作が行う。利用者が変換を書くと、ラベル・TTL・コメントを落とす
  余地が生まれる（FR-014b）。
- 受け取る一覧は、公開されているレコードを変換したものである。編集中の SOA は「更新前の
  状態」から変換されるため、排他のラベルは含まれない（同 D1）。
- 打ち切りを伝えられる引数を渡すのは、編集の処理が外部 I/O を行いうるためである。排他を
  失った時点でこの引数が打ち切られる。
- 編集しない項目はそのまま返せばよい。受け取った要素をそのまま返せば内容は変わらない。
- 返した一覧に SOA レコードまたは Zone Apex の NS レコードが含まれていない場合は、変換前の
  一覧のものを補う（同 D9）。取り込まれないため内容に影響しない。
- 返した一覧が空の場合は、反映を試みずに専用の番兵エラーを返す（FR-018、同 D11）。

### ラベルの扱い

| 対象 | 一括置き換えの後 | 理由 |
|---|---|---|
| 反映済みの SOA に付いたラベル | 残る | 取り込まないフラグにより既存の SOA が維持される（[research.md](./research.md) D1b） |
| 未反映の編集として書かれたラベル（排他） | 残らない | 未反映の編集は引き継がれない（同 D1） |
| SOA 以外のレコードのラベル | リクエストに含めれば残る | 保存されるのではなく、送ったから残る。入出力を同じ型にすることで落ちない（同 D9b） |

## 4. 排他の寿命

### `Do`（一括置き換えを伴わない場合）

```text
取得 ──▶ 保持（延長が周期的に走る）──▶ 解放
                  │
                  └─ 奪われた ──▶ 派生 context を打ち切る ──▶ 処理の終了を待つ ──▶ 解放を試みる
```

- 解放は `Unlock` を呼ぶ。保持者でない場合は `ErrNotLockHolder` が返るため、「自分が
  保持者である場合に限り解放する」（FR-007）はこれで満たされる（[research.md](./research.md) D8）。
- 延長が既に「奪われた」を報告している場合、解放時の `ErrNotLockHolder` は重ねて報告しない。

### `Apply`（一括置き換えを伴う場合）

```text
取得 ──▶ 保持 ──▶ 公開レコードの取得 ──▶ 編集 ──▶ 消費の印を立てる
                                                        │
                                                 （延長を止める）
                                                        ▼
                                              一括置き換えと反映
                                                        │
                                          （反映が排他を解く。実測済み）
                                                        ▼
                                              残っていた場合に限り解放
```

- 消費の印を立てる位置は「編集が終わり、一括置き換えを呼ぶ直前」である。これより早いと
  編集中の延長が止まり、遅いと反映中に延長が走って作り直される SOA を掴もうとする
  （[research.md](./research.md) D7）。
- 反映の後の解放は `Unlock` を呼び、`ErrNotLockHolder` を成功として扱う（FR-021、同 D8）。

## 5. エラー

| エラー | 意味 | 返る場面 |
|---|---|---|
| `ErrStillLock`（006） | 排他を取得できなかった | `Do` / `Apply` の入口 |
| `ErrNotLockHolder`（006） | 排他を失った | 延長で奪われたとき、解放で保持者でなかったとき |
| `ErrNoRecords`（新規） | 編集の結果が空である | `Apply`（API を呼ぶ前） |
| 利用者の処理が返したエラー | — | そのまま返す。ライブラリのエラーで置き換えない（FR-008） |

- 排他を失い、かつ利用者の処理もエラーを返した場合は、両方を判別できる形で返す
  （`errors.Is` がどちらにも一致する）。根本原因は排他の喪失だが、処理側のエラーも
  診断に必要である。
- API 由来のエラーはラップせずそのまま返す。`*dpf.GenericOpenAPIError` として
  `errors.As` で取り出し、`error_details` を参照できる状態を保つ（006 から継承）。

## 6. 検証規則の一覧

| 対象 | 規則 | 違反時 | 要件 |
|---|---|---|---|
| 編集の結果 | 1 件以上 | `ErrNoRecords`（API を呼ばない） | FR-018 |
| 取り込みの可否 | 常に「取り込まない」 | 実装上、変更する経路が無い | FR-015・FR-016 |
| 延長の間隔 | 正の値。既定は保持期間の 1/3 | 0 以下は無視して既定のまま（006 の Option の作法に合わせる） | FR-003 |
| 取得の待機の間隔 | 正の値 | 0 以下は無視（待たない） | FR-011 |
| 延長の goroutine | `Do` の復帰前に終了していること | — | [plan.md](./plan.md) 方針 5 |
| 利用者の処理の異常終了 | 捕捉しない | — | FR-009 |
