# 契約: 公開 API

**機能**: [../spec.md](../spec.md) | **計画**: [../plan.md](../plan.md) | **日付**: 2026-09-18

署名は実装時に確定するが、**外から見える約束**は本ファイルを正とする。

## 1. 排他を保持したままの実行

```go
func (t *Mutex) Do(ctx context.Context, fn func(ctx context.Context) error) error
```

- `fn` に渡される context は、`ctx` から派生したものである。**排他を他者に奪われた時点で
  打ち切られる。**
- 排他を取得できない場合、`fn` は呼ばれない。`ErrStillLock` を返す。
- `fn` が復帰したら、自分が保持者である場合に限り解放する。
- `fn` が返したエラーは、種類を判別できる形のまま返す。
- 排他を失った場合は `ErrNotLockHolder` を返す。`fn` もエラーを返していた場合は、両方を
  判別できる形で返す。
- **コールバックの引数は context 1 つだけである。** 一括置き換えが排他を解くという事情は
  この形に現れない（FR-017）。

### 約束

1. **保持期間は自動で延長される。** 利用者が延長を書く必要はない。`fn` がどれだけ長引いても
   保持は続く（延長が成功する限り）。
2. **`Do` が復帰した時点で、延長のための goroutine は終了している。** 呼び出し側のプロセスに
   goroutine を残さない。
3. **`fn` の異常終了（panic）は捕捉しない。** この場合、解放は行われず、排他は保持期間の
   経過によって解ける。
4. **打ち切りは通知であり、強制的な中断ではない。** `fn` が context を無視すれば走り続け、
   `Do` はその終了を待つ。
5. 1 レコードずつ変更して反映する流れは、この操作で足りる。その流れでは排他が解かれない
   （[../research.md](../research.md) D1）。

## 2. ゾーン全体の一括置き換え

```go
type ZoneRecordsEditor func(ctx context.Context, records []dpf.OverwriteRecordsInner) ([]dpf.OverwriteRecordsInner, error)

func NewZoneApplier(cr dpf.RecordsApi, cz dpf.ZonesApi, cj dpf.JobsApi, zoneID string, opts ...Option) *ZoneApplier
func (a *ZoneApplier) Apply(ctx context.Context, edit ZoneRecordsEditor, opts ...ApplyOption) error
```

**入力と出力は同じ型である。** 公開されているレコードからこの型への変換は `Apply` が行う。
利用者が変換を書くと、ラベル・TTL・コメントを落とす余地が生まれる
（[../research.md](../research.md) D9b）。

- `opts` は 006 の排他の Option をそのまま受け取り、内部の排他へ渡す。**排他そのものは
  公開しない。**
- `edit` に渡される context は、`Do` と同じく排他を失った時点で打ち切られる。
- `edit` に渡される一覧は、公開されているレコードを変換したものである。編集中の SOA は
  「更新前の状態」から変換されるため、排他のラベルは含まれない。

### 約束

1. **SOA レコードと Zone Apex の NS レコードは置き換わらない。** 取り込みの可否を決める
   2 つのフラグは常に「取り込まない」であり、利用者が変更する手段は無い。
2. **`edit` の結果に SOA と Zone Apex の NS が無ければ補う。** 取り込まれないため内容に
   影響しない。利用者はこれらを意識せずに `edit` を書ける。
3. **編集しなかった項目は変わらない。** 受け取った要素をそのまま返せば、ラベル・TTL・
   コメントはそのまま反映される。反映済みのラベルは一括置き換えで失われない
   （[../research.md](../research.md) D1b）。
4. **`edit` が空を返した場合は、反映を試みずに `ErrNoRecords` を返す。**
5. **反映の完了を待ってから復帰する。** 呼び出し側が非同期処理の完了を待つ必要はない。
6. **成功した場合、解放に起因するエラーは返らない。** 反映が排他を解くため、無条件の解放は
   行わない。反映の後に排他が残っていた場合に限り解放を試み、その結果を返す。
7. 反映より前のいずれかの段で失敗した場合は、排他を解放してから返す。

## 3. Option

| Option | 対象 | 既定値 | 0 値・空値の扱い |
|---|---|---|---|
| `WithRenewInterval(d)` | 延長の間隔 | 保持期間の 1/3 | 0 以下は無視 |
| `WithLockWait(d)` | 取得の待機の間隔 | 待たない | 0 以下は無視（待たない） |
| `WithApplyDescription(s)` | 反映に付けるコメント | 空 | 空文字は空のまま |

`WithRenewInterval` と `WithLockWait` は排他の Option（`Option`）である。
`WithApplyDescription` は一括置き換えの Option（`ApplyOption`）である。型を分けるのは、
可変長引数を 2 つ並べられないためであり、それぞれが自然な位置に収まる。

## 5. godoc に明記すること

### `Mutex.Do`

1. 保持期間が自動で延長されること。
2. 排他を失った時点で `fn` の context が打ち切られること。打ち切りは通知であり、強制的な
   中断ではないこと。
3. 延長が一時的に失敗した場合は次の周期で再試行すること。**失敗が続く間は、排他が実際には
   失効しているのに処理が走りうること。** 窓の長さは延長の間隔に依存すること。
4. `fn` の異常終了を捕捉しないこと。その場合に排他が残り、保持期間の経過で解けること。
5. 1 レコードずつ変更して反映する流れにはこの操作を使えばよいこと。
6. ゾーン全体の一括置き換えには `ZoneApplier` を使うこと（この操作では排他が解かれるため）。

### `ZoneApplier` / `Apply`

1. SOA レコードと Zone Apex の NS レコードが置き換わらないこと。フラグは固定であり
   変更できないこと。
2. 一括置き換えが排他を解くこと。したがって成功時に解放を行わないこと。利用者が解放を
   意識する必要がないこと。
3. `edit` の入力と出力が同じ型であり、編集しない要素はそのまま返せばよいこと。
   ラベル・TTL・コメントを落とす心配がないこと。
4. `edit` が空を返した場合の扱い。
5. 反映の完了を待ってから復帰すること。
